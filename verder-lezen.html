    14. Verder lezen

    Dit document heeft een inleiding gegeven in de taal Kotlin en de meestgebruikte bibliotheken voor het schrijven van gelaagde applicaties, netwerkclients en -servers en webservices op de Java Virtual Machine. Hier volgen de belangrijkste onderwerpen die hierop voortbouwen.

    14.1. XML-documenten verwerken

    JSON heeft XML grotendeels vervangen voor gegevensuitwisseling, maar XML wordt nog steeds gebruikt (configuratiebestanden, documentformaten, bestaande SOAP-services). Kotlin gebruikt rechtstreeks de XML-API van de JDK, in het pakket [javax.xml]:

    • DOM ([DocumentBuilder], [Document], [Element]): het document wordt als boom in het geheugen geladen, die vervolgens wordt doorlopen en gewijzigd;
    • StAX ([XMLStreamReader], [XMLStreamWriter]): het document wordt on-the-fly gelezen of geschreven, zonder volledig in het geheugen te worden geladen;
    • XPath ([javax.xml.xpath]) om een document te bevragen en XSLT ([javax.xml.transform]) om het te transformeren.

    Naast de JDK kan Jackson met zijn module [jackson-dataformat-xml] XML lezen en schrijven, net zoals hij dat voor JSON doet (Hoofdstuk 5), en ondersteunt ook de bibliotheek kotlinx.serialization van JetBrains, die serialisatiecode tijdens het compileren genereert, door de gemeenschap ontwikkelde XML-formaten.

    14.2. Webapplicaties

    Hoofdstuk 13 behandelt alleen webservices (applicaties die gegevens produceren). Voor webapplicaties die HTML-pagina's genereren, of voor andere manieren om webservices in Kotlin te schrijven, zijn de volgende mogelijkheden beschikbaar:

    • Spring MVC met een template-engine zoals Thymeleaf: pagina's die op de server worden gegenereerd. Spring ondersteunt Kotlin net als Java (dataklassen, coroutines in controllers, Kotlin voor routeconfiguratie); de auteur schreef de cursus „Stapsgewijze inleiding tot het Spring-webframework” (september 2026);
    • Ktor, het webframework van JetBrains, geschreven in en voor Kotlin: HTTP-servers en -clients die zijn gebouwd op de coroutines uit Hoofdstuk 9, geconfigureerd met Kotlin-code in plaats van met annotaties;
    • andere JVM-frameworks die Kotlin ondersteunen: Quarkus, Micronaut, Javalin en de applicatieservers van Jakarta EE;
    • interfaces die in JavaScript zijn geschreven (Vue.js, Angular, React) en Kotlin-webservices gebruiken; de auteur schreef de cursus „Stapsgewijze inleiding tot het framework Vue.js” (september 2026). Kotlin zelf kan worden gecompileerd naar JavaScript (Kotlin/JS) of naar WebAssembly (Kotlin/Wasm), waarmee ook de clientzijde in Kotlin kan worden geschreven.

    14.3. Mobiele applicaties en desktopapplicaties

    Dit document behandelt geen grafische gebruikersinterfaces: tegenwoordig worden beheerapplicaties meestal met webinterfaces gebouwd. Toch is dit een gebied waar Kotlin veel wordt gebruikt:

    • op Android is Kotlin de door Google aanbevolen taal en wordt de gebruikersinterface gebouwd met Jetpack Compose, een declaratieve bibliotheek die volledig in Kotlin is geschreven; coroutines (Hoofdstuk 9) worden gebruikt om de gebruikersinterface responsief te houden tijdens netwerk- of databasetoegang;
    • Compose Multiplatform, van JetBrains, breidt Compose uit om met dezelfde code desktop- (Windows, Linux, macOS), iOS- en webinterfaces te schrijven;
    • Meer in het algemeen maakt Kotlin Multiplatform het mogelijk om code voor bedrijfslogica (bijvoorbeeld de lagen [business] en [dao] uit Hoofdstuk 6) te delen tussen JVM, Android, iOS (via Kotlin/Native, dat machinecode genereert zonder virtuele machine) en het web;
    • op de JVM blijven de Java-bibliotheken Swing en JavaFX bruikbaar vanuit Kotlin. De concepten uit hoofdstuk 7 (event listeners) en hoofdstuk 9 (terugkeren naar de GUI-thread met [Dispatchers.Main]) zijn hier rechtstreeks van toepassing.

    14.4. Tests

    Hoofdstuk 6 introduceert JUnit en [kotlin.test]. Deze worden vaak aangevuld met:

    • Kotest, een testframework dat voor Kotlin is geschreven en meerdere stijlen om tests te schrijven biedt, met een uitgebreide bibliotheek van assertions ([list shouldHaveSize 7]);
    • MockK, de bibliotheek van „mocks” (gesimuleerde objecten) voor de lagen waarvan de te testen laag afhankelijk is, ontworpen voor Kotlin (final klassen, objecten, suspend-functies); Mockito blijft bruikbaar;
    • kotlinx-coroutines-test, waarmee tests van code op basis van coroutines worden uitgevoerd met een virtuele klok: een [delay(10_000)] wordt onmiddellijk uitgevoerd;
    • Testcontainers, waarmee gedurende de integratietests een echte database (MySQL, PostgreSQL…) in een Docker-container wordt gestart;
    • de testhulpmiddelen van Spring Boot ([@SpringBootTest], [MockMvc]) om een webservice te testen zonder die uit te rollen.

    14.5. Prestaties

    Een Kotlin-programma wordt uitgevoerd door de Java Virtual Machine (JVM): het profiteert van just-in-time-compilatie en optimalisaties tijdens de uitvoering, met prestaties die gelijkwaardig zijn aan die van een Java-programma. Tot de hulpmiddelen die een stap verder gaan behoren:

    • het hulpmiddel JMH („Java Microbenchmark Harness”), dat rechtstreeks in Kotlin of via de Gradle-plug-in kotlinx-benchmark kan worden gebruikt om de prestaties van code nauwkeurig te meten, waarbij rekening wordt gehouden met de opwarmfase van de virtuele machine;
    • JDK Flight Recorder en JDK Mission Control, die het gedrag van een programma in productie opnemen en analyseren; IntelliJ IDEA bevat een profiler en een coroutine-debugger;
    • ahead-of-time-compilatie naar native code met GraalVM Native Image: een zelfstandig uitvoerbaar bestand dat in enkele milliseconden start, ten koste van beperkingen op het gebruik van reflectie; Spring Boot en Quarkus kunnen dergelijke uitvoerbare bestanden genereren vanuit Kotlin-code;
    • de keuze van de garbage collector (standaard G1, ZGC voor zeer korte pauzes bij grote geheugenheaps).

    14.6. Uitrol

    Een Kotlin-programma wordt op dezelfde manier uitgerold als een Java-programma: als een [.jar]-archief dat wordt uitgevoerd door een JDK die op de machine is geïnstalleerd ([java -jar application.jar]), mits de standaardbibliotheek van Kotlin is meegeleverd (dit doen de scripts die door [gradlew installDist] worden gegenereerd, hoofdstuk 2; Spring Boot genereert een zelfstandig [.jar] dat al zijn bibliotheken bevat), als een zelfstandige applicatie die een tot het strikt noodzakelijke teruggebrachte virtuele machine insluit (de hulpmiddelen [jlink] en [jpackage] van de JDK), of in een Docker-container (Spring Boot genereert rechtstreeks een containerimage via [gradlew bootBuildImage]).

    14.7. Bronnen

    • de officiële website van Kotlin, met de documentatie, tutorials en „What’s New”-pagina’s voor elke release: https://kotlinlang.org;
    • de online sandbox Kotlin Playground om Kotlin-code in een browser uit te proberen;
    • de oefeningen Kotlin Koans , beschikbaar op de website van Kotlin en in IntelliJ IDEA;
    • de voorstellen voor taalontwikkeling (KEEP), om op de hoogte te blijven van wat er nieuw is in komende versies: https://github.com/Kotlin/KEEP;
    • de broncode van de compiler en de standaardbibliotheek, beschikbaar op GitHub: https://github.com/JetBrains/kotlin, en de broncode van de coroutines: https://github.com/Kotlin/kotlinx.coroutines;
    • de documentatie van de Java API SE 25, voor de JDK-klassen die vanuit Kotlin worden gebruikt: https://docs.oracle.com/en/java/javase/25/docs/api/;
    • de boeken *Kotlin in Action* (Manning) en *Effective Kotlin* van Marcin Moskała en, voor concurrency op de JVM, *Java Concurrency in Practice* van Brian Goetz e.a. (Addison-Wesley).
